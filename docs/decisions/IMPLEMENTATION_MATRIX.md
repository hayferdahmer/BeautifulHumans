# Матрица реализуемости Beautiful Humans

**Статус:** архитектурная оценка по проектным решениям раундов 1–10.  
**Не является:** подтверждением готовности перечисленных систем.

## Легенда

- **Основа есть** — в репозитории уже присутствует частичная реализация.
- **Реализуемо** — можно реализовать в рамках Lua-мода при наличии адаптеров и тестов.
- **С оговорками** — нужна абстракция, ограничение масштаба, дополнительные игровые ресурсы или проверка API.
- **Не подтверждено** — нельзя считать доступным без проверки в целевой сборке игры.

| Область | Текущее состояние по репозиторию | Следующий обязательный шаг |

## Уровни детализации симуляции

### L0 — Active / Full

Игрок, ближайшие активные сущности и текущие взаимодействия. Высокая частота обновлений, подробные состояния и немедленная обратная связь.

### L1 — Nearby / Reduced

Сущности в зоне интереса, которые не взаимодействуют прямо сейчас. Реже обновляются, но сохраняют индивидуальные профили и причинно-следственные связи.

### L2 — Regional / Background

Удалённые NPC, животные, поселения, предприятия и экосистемы. Обновляются пакетами, по расписанию или при значимых событиях.

### L3 — World / Strategic

Глобальная экономика, климатические тенденции, миграция, войны и другие процессы. Событийные или агрегированные расчёты на длительных интервалах.

Переходы между уровнями не должны сбрасывать состояние. При повышении детализации система восстанавливает локальное состояние из агрегатов, временных меток и сохранённых параметров.

## Главные технические риски

1. **Ограничения API PZ:** NPC-человек, анимации, разрушения, животные и некоторые сетевые возможности требуют отдельного исследования.
2. **Сохранения:** большие журналы событий и полные исторические снимки могут раздувать modData. Нужны лимиты, сегментация и отдельное хранение только там, где API это позволяет.
3. **Синхронизация:** нельзя отправлять полную модель мира каждый кадр. Используются ревизии, дельты, события и запрос снимка при входе/восстановлении.
4. **Клиентская недоверенность:** любой результат, влияющий на здоровье, предметы, экономику, прогресс или мир, перепроверяется сервером.
5. **Производительность:** каждый модуль должен иметь бюджет, ограничения сущностей и измеряемые сценарии.
6. **Совместимость:** поддержка фиксируется по точной сборке игры и повторяется после обновления Build 42.

## Критерий допуска системы в основную ветку

- описаны входы, выходы, владелец состояния и зависимости;
- нет циклических зависимостей;
- есть unit-тесты чистых правил;
- есть проверки миграции/сохранения для постоянных данных;
- сетевые изменения проверяются на сервере;
- есть ограничения роста и rate limits;
- есть интеграционный сценарий в целевой игре;
- производительность измерена или явно помечена как ещё не измеренная.
