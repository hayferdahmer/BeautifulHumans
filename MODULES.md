## 3. Границы ответственности

### Core

Может:

- регистрировать модули;
- выдавать конфиг;
- эмитить события;
- писать диагностику;
- проверять версию игры.

Не может:

- лечить;
- торговать;
- менять здоровье;
- знать о зонах тела;
- содержать UI.

### Persistence

Может:

- читать/писать `modData`;
- мигрировать;
- ремонтировать;
- карантинировать.

Не может:

- интерпретировать медицинские правила;
- менять состояние без запроса владельца данных.

### Anatomy

Может:

- создавать/удалять травмы;
- считать impairment;
- тикать заживление.

Не может:

- менять базовое здоровье;
- открывать UI;
- доверять клиенту.

### Medical

Может:

- проверять действие;
- менять травму;
- возвращать `consume`.

Не может:

- напрямую работать с инвентарём;
- запускать анимации;
- отправлять сетевые пакеты.

### Integration

Может:

- регистрировать события;
- наблюдать базовое состояние;
- вызывать публичные API.

Не может:

- содержать медицинские формулы;
- быть обязательным для доменных тестов.

## 4. Правила добавления модуля

1. Уникальный `id` формата `bh.<name>`.
2. Указать `version`.
3. Указать `requires` (только реальные зависимости).
4. `init` не должен выполнять тяжёлую работу и не должен падать без
   диагностики.
5. Публичные функции документировать.
6. Добавить unit-тесты.
7. Добавить интеграционный сценарий, если модуль сохраняет состояние.
8. Обновить `docs/MODULES.md` и `docs/ARCHITECTURE.md`.
9. Проверить отсутствие циклов.
10. Проверить, что модуль можно не устанавливать.

---

## 5. Почему модули не обязательны все сразу

ТЗ требует, чтобы установка необязательного модуля без зависимости не
приводила к ошибке загрузки. Поэтому:

- зависимости объявляются явно;
- отсутствующая зависимость блокирует только зависимый модуль;
- независимые модули продолжают работу;
- Core сообщает `failed`/`skipped` в диагностике;
- тестовый мод проверяет этот сценарий.

---

## 6. Планируемое объединение пакетов

На Stage 2–3 допустимо выпускать:

- `BeautifulHumansCore` — Core + Persistence + Anatomy + Physiology + Medical;
- `BeautifulHumansMedical` — UI и расширенные действия;
- `BeautifulHumansUndead` — зомби;
- `BeautifulHumansWorld` — материалы, инженерия, окружение.

Функциональные границы сохраняются, даже если модули лежат в одном пакете.
